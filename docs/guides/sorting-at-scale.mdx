{user.name ? <>{user.name}, here's</> : <>Here's</>} what to expect when you send large lists to `POST /sort`.

| List size | Typical time | Notes |
| --- | --- | --- |
| 1,000 numbers | under 5 ms | Fine for any request |
| 100,000 numbers | about 200 ms | Send `/sort`, not `/sort/steps` |
| 1,000,000 numbers | 2 to 3 s | Split the list and merge the sorted parts yourself |

## Why not `/sort/steps` for big lists?

`/sort/steps` returns every merge, and a list of *n* numbers has *n − 1* merges. For 100,000 numbers that's a response of several megabytes. Use it for teaching and debugging, not production traffic.

## Memory

Merge sort needs extra memory equal to the input size. The API holds the whole list in memory, so keep a single request under about 10 MB of JSON.
